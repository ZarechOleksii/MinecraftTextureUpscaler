# Open Knowledge Format (OKF)

OKF is how this repository documents itself. Instead of file-header comments, every directory has one `OKF.md` that
says what each file in it contains, what it does, and which files to read next. It is written for a contributor (or an
AI assistant) who has never seen the repository: start at [the root OKF.md](../OKF.md) and follow the links.

## What an `OKF.md` looks like

```markdown
---
okf: 1
path: src/regen4x
purpose: One sentence: what this directory is for.
---

# Title

Two or three sentences of context: how the files fit together, which direction dependencies go.

## Files

- [params.py](params.py): what it contains and what it does, in one or two sentences.
  Related: [presets.py](presets.py), [../../tests/test_params_and_presets.py](../../tests/test_params_and_presets.py).

## Subdirectories

- [tools/](tools/OKF.md): one line on what is in it.
```

Rules for the content:

- **One entry per file**, written as a relative markdown link to the file, followed by what the file contains and what
  it does. Say what is not obvious from the name; do not restate the name.
- **`Related:` points onward**: the file's tests, the file it is generated from or feeds, the spec that defines it.
- **Subdirectories** are linked to their own `OKF.md`.
- **No bloat**: no function-by-function listings (the code and its docstrings have those), no usage text that the
  README or `--help` already holds (link to it), no history (git has it).
- Keep comments in code for the *why* of a non-obvious line. Describing what a file is for belongs here, not in a
  header comment. The one exception is a command-line tool's module docstring, which is also its `--help` text.
- The name is `OKF.md` in capitals. File systems that ignore case (Windows, macOS) would merge it with a lower-case
  `okf.md`, which is why this page is not called that.

## What the check enforces

`python .github/scripts/okf_check.py` (run by the `okf` job in [CI](../.github/workflows/ci.yml) and by
[tests/test_okf.py](../tests/test_okf.py)) reads the tracked files and fails when:

1. a directory that holds tracked files has no `OKF.md`, or the front matter lacks `okf`, `path` or `purpose`, or
   `path` is not the directory;
2. a file in the directory (images excluded) has no entry linking to it, or a subdirectory is not linked to its
   `OKF.md`;
3. a relative link in an `OKF.md` points at nothing.

`docs/presets/` is generated by `regen4x-docs` and is described in [docs/OKF.md](OKF.md) instead of having its own
`OKF.md`.

On a pull request (`--base BRANCH`) the check also warns, without failing, when a file changed but its directory's
`OKF.md` did not: re-read the entry and update it if the file now contains or does something different.
